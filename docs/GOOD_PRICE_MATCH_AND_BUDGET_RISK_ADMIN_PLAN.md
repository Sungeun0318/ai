# 착한가격업소 매칭 개선 + 예산 위험 관리자 노출 기획

## 목표

1. 영수증 가게가 실제 착한가격업소인지 더 정확하게 검증한다.
2. 매칭 근거를 관리자에서 확인할 수 있게 점수와 사유를 저장한다.
3. 2차 기능인 예산 초과 위험 예측 결과를 관리자 통계 화면에 보여준다.

## 용어

- 착한가격업소 매칭: 영수증의 가게명/주소를 행정안전부 착한가격업소 API 데이터와 비교해서 인증하는 작업.
- 후보 검색: 전체 업소를 다 비교하지 않고, 영수증 주소의 지역 키워드로 먼저 검색 범위를 줄이는 작업.
- 매칭 점수: 가게명 유사도와 주소 유사도를 합산한 인증 근거 점수.
- 예산 위험 예측: 방별 예산, 지출, 영수증 개수 등을 바탕으로 LOW/MEDIUM/HIGH 위험도를 산출하는 2차 AI 기능.

## Step 1. 착한가격업소 후보 검색 개선

현재 문제:

- 앞쪽 1000개 업소만 가져와 비교한다.
- 실제 업소가 API 뒤쪽 페이지에 있으면 미매칭될 수 있다.

개선:

- 영수증 주소에서 시/군/구 또는 앞쪽 지역 키워드를 추출한다.
- 주소 키워드로 `GoodPriceStoreClient.searchByAddressKeyword()`를 먼저 호출한다.
- 후보가 없을 때만 기존 전체 페이지 검색을 fallback으로 사용한다.

검증:

- 주소가 있는 영수증은 주소 키워드 검색이 먼저 실행된다.
- 주소 검색 결과가 비어도 기존 fallback으로 동작한다.

## Step 2. 가게명 + 주소 복합 점수로 인증

현재 문제:

- 가게명만 완전 일치하면 주소가 약해도 인증될 수 있다.

개선:

- 가게명 점수와 주소 점수를 분리한다.
- 인증 기준:
  - 가게명 점수 80 이상
  - 주소 점수 40 이상
  - 총점 120 이상
- 이름과 주소가 모두 어느 정도 맞아야 `goodPriceMatched=true` 처리한다.

검증:

- 이름만 맞고 주소가 비어 있거나 다르면 미매칭된다.
- 이름과 주소가 모두 맞으면 매칭된다.

## Step 3. 매칭 점수/사유 저장

추가 저장값:

- `receipts.good_price_match_score`
- `receipts.good_price_match_reason`

관리자 표시:

- 영수증 상세의 착한가격업소 매칭 영역에 점수와 사유를 보여준다.

검증:

- 매칭 성공 시 점수/사유가 저장된다.
- 미매칭 시 점수는 0 또는 null, 사유는 미매칭 이유로 저장된다.

## Step 4. 예산 위험 예측 관리자 노출

현재 상태:

- AI 서버에는 `POST /api/v1/predictions/budget-risk`가 있다.
- 관리자 통계 화면은 1차 소비 인사이트만 보여준다.

개선:

- 백엔드 관리자 API 추가:
  - `GET /admin/ai/predictions/budget-risk`
- 백엔드가 rooms, receipts, budgets 데이터를 모아 AI 서버에 전달한다.
- 관리자 JSP `/admin/insights` 하단에 "예산 초과 위험 예측" 테이블을 추가한다.

표시 컬럼:

- 방 번호
- 방 이름
- 위험도
- 위험 점수
- 예상 최종 지출
- 예상 예산 사용률
- 권장 다음 소비 한도
- 위험 사유

검증:

- AI 서버 직접 호출이 200으로 응답한다.
- 백엔드 관리자 API가 200으로 응답한다.
- 관리자 통계 화면에서 예산 위험 테이블이 보인다.
